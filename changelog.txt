custom-controls changelog
=========================

Legend
------
* : fixed
! : changed
+ : added
- : removed


unreleased
----------
* DriverJs, Validator: a view rebuilt by view_display (e.g. after a navigation back) no longer starts the last tour or runs the last check again - the trigger value a new control instance is built with counts only when the previous instance at the same binding did not already have it
! DriverJs: popover title, description, progress and button texts are plain text now (escaped) - driver.js wrote them with innerHTML; allowhtml = `true` takes HTML again, sanitized with DOMPurify (purifyurl)
* ChartJs: a plugin (datalabels, autocolors, deferred) is handed to the one chart that names it instead of being registered page-wide, where it changed every other chart on the page; annotation and the chart types venn and wordcloud still need Chart.js' registry
* Validator: required fails an unticked CheckBox, a Switch that is off (Switch was not read at all) and a MultiComboBox or MultiInput with nothing selected - their selected keys / tokens are read instead of the typed text
+ CDN build: every library URL carries a Subresource Integrity hash (sha384, generated by npm run vendor and checked in CI); the Font Awesome IconPool directory is pinned to a commit of its repository
* CodeEditor: no second editor (duplicate id) when the control re-rendered while sap.ui.codeeditor was still loading
* ExportSpreadsheet: the SAPUI5/OpenUI5 check runs once per page, asynchronously, instead of a synchronous version info request on every rendering
* NetworkStatus: the icon size is set outside the renderer; a stopped ping monitor is dropped after one interval and a stale result is not shown as current
* AnimateCss: several instances share the page-wide variables - the last one rendered wins, and exit( ) restores the previous instance's or the page's own values instead of removing them
* UI5 1.71 to 1.92: Util.isDestroyed probes the destroyed flag (isDestroyed( ) is 1.93) - async callbacks no longer touch a destroyed control; SignaturePad, NetworkStatus and ScanInput use the shared Util helpers
+ FloorPlan: an item with disabled = abap_true takes no click - no itempress, no selection, no pointer cursor
+ ScanInput: beeponsuccess = `true` plays a short, high tone when valuestate turns to Success - the scan was taken
+ FloorPlan: zoomable = `false` makes the plan a fixed picture of the whole - no wheel, drag, pinch, keys or buttons, the page scrolls as usual, a click still selects
+ FloorPlan (z2ui5_cl_cci_floor_plan, sample 18): a plan of boxes from an ABAP table, each with a position, a state and a fill level, that the user zooms and pans with the wheel, a drag or two fingers; the closer the view, the more text a box shows, a click raises "itemPress" with its key, and "fitkeys" flies the viewport to items from ABAP. Plain SVG, no library
+ Gauge (z2ui5_cl_cci_gauge, sample 16): a round gauge with a scale, coloured zones and a needle that follows the bound value, drawn by canvas-gauges 2.1.7
+ GridStack (z2ui5_cl_cci_gridstack, sample 17): boxes on a grid from an ABAP table, shown or dragged and resized by the user with gridstack.js 14.1.1; the new positions are written back into the table before the event "change" is raised
+ ScanInput: a focus sequence over several scan fields - bind keepfocus of each field to a flag; the field whose flag turns on while it is on screen takes the focus, also from another text field (a popup, a hidden or a disabled field still make it wait)
+ ScanInput: uppercase = `true` turns what is typed, scanned or pasted into capital letters in the field, so value, submit and change carry them
! BREAKING: four classes renamed so that every class name has at most 25 characters and the namespace rename takes a name of the full 10 characters (it was capped at 6): z2ui5_cl_cci_rich_text_editor -> z2ui5_cl_cci_rich_text, z2ui5_cl_cci_barcode_scanner -> z2ui5_cl_cci_barcode_scan, z2ui5_cl_cci_network_status -> z2ui5_cl_cci_net_status, z2ui5_cl_cci_signature_pad -> z2ui5_cl_cci_signature. Methods, parameters, types and constants are unchanged, and so are the controls in the BSP (z2ui5_cci.cc.RichTextEditor, ...). An app changes the class name it calls; after the abapGit pull the four old classes are still on the system - abapGit does not delete them - and must be deleted by hand (SE24 or ADT) once no app uses them
